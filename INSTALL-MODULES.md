# Installing the twenty modules into your vibeshop repo

This bundle holds only the net-new artifacts. Your base app (generated by `create-vibeshop.py`)
is unchanged; these drop on top of it.

## 1. Extract at the repo root, on main

    cd vibeshop
    git checkout main
    tar xzf vibeshop-modules.tar.gz        # adds exploits/ tests/ modules/ .pkg/,
                                           # MODULES.md, and overwrites scripts/audit.sh
    git add -A
    git commit -m "Add twenty exploit/test/fix modules and the audit harness"

`scripts/audit.sh` is replaced: the new one keeps `--modules` and adds `--branches`. If you want to
diff it against yours first, extract to a temp dir instead.

## 2. Build the fix branches

    bash scripts/make-fix-branches.sh      # creates fix/01 .. fix/20, each = main + its .pkg fix

## 3. Validate on the lab VM

    make reset
    bash scripts/audit.sh --modules        # on main: every exploit exits 0, every test exits 1
    bash scripts/audit.sh --branches       # plus every fix/NN: test 0, exploit 1, back to main

Spot-check one module end to end:

    make reset && make verify N=18          # exploit then test, on main
    git checkout fix/18 && make reset
    bash tests/18/test.sh                    # exit 0
    bash exploits/18/run.sh                  # exit 1 (FIXED)
    git checkout main

## Notes

- These scripts were written against the generated source and syntax-checked (`bash -n`,
  `node --check`, `py_compile`), but they were not run against a live stack during authoring.
  Run the audit on your VM; it is the thing the claim rests on.
- Module 2 needs a full clone (real `.git` history). Module 6 needs docker. Modules 14 and 19 have a
  browser step described in the module notes and post 2.
- `.pkg/` is the fix source of record on `main`. Edit a fix there, then re-run
  `scripts/make-fix-branches.sh NN` to rebuild that branch.
